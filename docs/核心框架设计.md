# 核心框架设计（v0.1）

> 状态：v0.1 已落地。定位为"当前能力盘点"中缺失的**统一应用层 + 场景装配入口 + 生命周期契约 + 运行时自检**。

## 一、背景与问题（对抗式审查结论）

以下结论基于场景序列化数据与代码逐项核对，非文件名推断。

### 风险（本框架已覆盖或已缓解）

- **双输入/双状态入口**：移动/攻击存在旧脚本路径与 FSM 路径两条入口。→ 框架仲裁：FSM 模式禁用 `跳跃射箭`、`基础移动` 让出控制权。
- **状态卡死**：DodgeState 无法回 Idle。→ 已修复。
- **"能编译但场景走不到"**：FSM 从未装配进场景。→ `PlayerCombatBootstrap` 成为单一装配入口，一条命令装配。
- **失败不可观察**：装配缺失只有运行时 NRE。→ `RuntimeDiagnostics` 输出显式问题列表。

## 二、架构决策

### D1：组合根（Composition Root）模式

新增 `PlayerCombatBootstrap` 作为玩家战斗管线的**唯一装配入口**，在 `Awake` 按固定顺序装配：

```
数据层    ChaState（统一伤害管线） → BuffController（Buff 生命周期）
表现层    PlayerAnimationPresenter（动画/朝向/命中盒）
决策层    PlayerInputReader（输入→意图） → CombatDecisionComponent（体力/冷却决策）
执行层    SkillExecutor（技能配置执行） → CombatStateMachine（FSM 调度）
仲裁      Fsm 模式：基础移动让权、跳跃射箭禁用
```

选择理由：
- 消除"编辑器手点 + 运行时 `AddComponent` 隐式添加"的双路径（现状两套都存在）。
- 组件生命周期统一在 `Awake` 内完成，`Start` 只做自检，顺序确定。
- 反例：全局单例/静态 ServiceLocator 会引入隐藏依赖，本原型规模不需要。

### D2：旧脚本仲裁而非删除

`基础移动` 保留受击/死亡/回血逻辑（`基础移动.cs` 职责说明），`跳跃射箭` 的跳跃/射箭**尚未迁移进 FSM**，本框架选择显式禁用而非并行运行，避免双写 `rb.linearVelocity`。迁移到 FSM（或新输入系统）在 v0.2 处理，本框架只保证单入口。

### D3：单帧单次输入读取

`CombatStateMachine.Update` 每帧只调一次 `inputReader.GetIntent()`，写入 `CombatContext.Intent`；状态机内部从 `ctx.Intent` 读取。避免同一帧多次读输入导致状态间行为不一致（现状 `IdleState`/`MoveState`/`AttackState` 各自调用 `GetIntent()`，输入事件如 `GetMouseButtonDown` 在同一帧多次调用结果一致，但属隐患）。

### D4：失败可观察

- `CombatStateMachine.ChangeState`：空状态、非法转换均输出 `LogError`/`LogWarning`，不再静默。
- `RuntimeDiagnostics`：场景启动后输出装配问题清单（缺失组件/引用/技能配置），运行期不可见的装配错误在编辑器可见。

## 四、装配链（从场景启动到实际调用）

```
Unity 场景加载
  → PlayerCombatBootstrap.Awake()         装配根：AddComponent 缺失组件、Configure FSM、仲裁旧脚本
  → 各组件 Awake（PlayerInputReader 绑相机 / ChaState 注册属性表 / Presenter 自绑定）
  → CombatStateMachine.Start()            未 Configure 时自绑定回退 → 进入 IdleState
  → PlayerCombatBootstrap.Start()         RuntimeDiagnostics.Run() 输出自检报告
  → CombatStateMachine.Update()           读输入 → ctx.Intent → currentState.Execute(ctx)
```

生命周期覆盖：**创建（AddComponent）→ 启用（组件启用）→ 更新（FSM Update）→ 禁用/销毁（场景卸载，组件无静态引用、无跨场景单例）**。本次不引入跨场景常驻对象。

## 五、诊断契约

进入 Play Mode 后查看 Console 的 `[Diagnostics]` 日志：

- **问题项**（`LogWarning`，必须处理）：缺少 ChaState/BuffController/InputReader/Decision/StateMachine/Presenter、表现层引用缺失（动画/命中盒）、mainSkill 未配置。
- **信息项**（`Log`，提示性）：旧脚本并存、让权/禁用仲裁结果、selfBuffSkill 未配置。

验收标准：装配完成后 Play Mode 应看到**零问题项**；`基础移动` 不再写速度（FSM 接管）、`跳跃射箭` 被禁用。
