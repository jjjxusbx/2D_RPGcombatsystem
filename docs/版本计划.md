## v0.1 核心框架（✅ 已交付）

**交付物**：`PlayerCombatBootstrap`（装配根）、`RuntimeDiagnostics`（运行时自检）、`CompositionSetup`（编辑器装配工具）、FSM 加固（Configure/自绑定/intent 缓存/可观察错误）、DodgeState 状态卡死修复、输入键位配置化。

**验收结果**：
- `dotnet build .\Assembly-CSharp.csproj` ✅ 0 错误
- `dotnet build .\Assembly-CSharp.Player.csproj` ✅ 0 错误
- 待 Unity 内验证：装配菜单执行 → Play Mode `[Diagnostics]` 零问题项 → 移动/攻击/闪避 FSM 接管

**遗留**：Unity 场景尚未挂载 bootstrap（需人工执行装配菜单）；跳跃/射箭被禁用，待 v0.2 迁移。

## v0.1.5 极简 Rogue 验证（⏳ 下一目标，2 周）

**目标**：在不触碰"暂不可复用"模块（BuffController/InventoryManager/CombatStateMachine 扩展）的前提下，验证"砍怪-爆装-变强"核心爽点。

**玩法范围**（依据《策划流程与双档方案.md》三.A）：
- 进房间 → 清怪 → 掉灰烬碎片 → 祭坛房三选一强化 → BOSS → 结算
- 强化走 `ChaState.ApplyModifier(source=局会话)`，跑局结束 `RemoveModifiersFromSource` 清空
- 必做 5 数值：Atk / MaxHealth / AttackRate / MoveSpeed / Growth（全部已存在于 ChaState）

**开发任务拆解**：
1. `RunManager`：局会话生命周期（开始/结束/死亡结算/属性清场）——复用装配根模式
2. 房间流：战斗房（现有敌人）+ 祭坛房（三选一 UI）+ BOSS 房（可先用史莱姆王占位）
3. 掉落：击杀掉碎片（`ChaState.onDeath` 订阅）+ 拾取（PickupRange）
4. 结算 UI：本局碎片、击杀数、局外货币

**前置条件**：SaveManager 扩展（版本号 + 原子写入）——仅局外货币需要持久化。

**验收清单**：
- [ ] 一局可循环 3+ 房间，强化即时生效（面板可见）
- [ ] 死亡结算回营地，属性还原（`RemoveModifiersFromSource` 生效）
- [ ] 重启后局外货币保留（SaveManager 版本化）
- [ ] `[Diagnostics]` 零问题项
- [ ] 两个 csproj 构建通过

## 版本计划维护规则

1. 每版结束必须完成复盘模板，未完成不得进入下一版。
2. 验收清单是硬门槛：两个 csproj 构建通过 + 对应 Play Mode 清单，缺一不可。
3. 涉及架构/管理器变更时，先按《用户规则》对抗式审查协议输出"事实/风险/结论"，再决定复用、修复或重写。
4. 文档间引用：本文件 ↔《核心框架设计.md》验收清单 ↔《策划流程与双档方案.md》双档方案 ↔ GDD 数值表。
