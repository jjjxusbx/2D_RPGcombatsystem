## 3. Proposed Changes (specific files + what / why / how)

> Module location: new `Roguelike/` directory (extend the `Roguelike.Run` namespace family with `Roguelike.Flow` / `Roguelike.UI`, or keep `Roguelike.Run`), isolated from the combat pipeline. All scripts get `.meta`.

### 1. Room flow controller (new)
- `Assets/C#/Roguelike/RogueRoomFlowController.cs` (new)
  - **What / why**: v0.1.5 task 2 "room flow". Governs the in-run "combat room → altar room → next combat room → … → boss room → settlement" meta-loop state machine; no conflict with the combat FSM.
  - **How**: reference `RunManager`; call `StartRun` on entry; subscribe to the current room's enemies' `ChaState.onDeath` (or `EnemyBase.onDeath`) → `RunManager.NotifyKill()` and evaluate whether the room is cleared; when clear → `NotifyRoomCleared()` → open the altar UI (or advance to boss/settlement); boss death → `RunManager.EndRun(true)`; player death → `EndRun(false)`. Emit `[Diagnostics]` logs for room transitions.

### 2. Fragment drop & pickup (new)
- `Assets/C#/Roguelike/FragmentDrop.cs` (new)
  - **What / why**: v0.1.5 task 3 "drops". Verifies the "kill → drop → pick up → strengthen" loop.
  - **How**: attached to a spawned fragment GameObject (`SpriteRenderer` + `Collider2D`, IsTrigger); when the player enters `PickupRange` or overlaps, destroy and call `RunManager.AddFragments(n)`; `n` derived from the enemy's `ChaState.Growth` (or a fixed value), keeping the dropped count a minimal observable integer.
- `Assets/C#/Roguelike/FragmentSpawner.cs` (new, may be merged into room flow)
  - **How**: subscribe to enemy `ChaState.onDeath`, `Instantiate` fragments at death position. If enemies have no dedicated spawner, handle it centrally in `RogueRoomFlowController`.

### 3. Altar 3-choice UI (new)
- `Assets/C#/Roguelike/AltarChoiceUI.cs` (new)
  - **What / why**: v0.1.5 task 2 "altar room 3-choice".
  - **How**: UGUI Panel; 3 options each bound to an `AttributeModifier` preview (Atk / MaxHealth / AttackRate / MoveSpeed / Growth, pick 3, with values); on click → `RunManager.ApplyRoomBuff(mod)` → hide and let room flow advance. Option data via `ScriptableObject` or in-memory arrays to avoid hardcoding and hand-written scenes.

### 4. Settlement UI (new)
- `Assets/C#/Roguelike/SettlementUI.cs` (new)
  - **What / why**: v0.1.5 task 4 "settlement UI".
  - **How**: UGUI Panel; on win/loss show this run's fragments, kills, and settled crystals (read `RunManager.Session` + `RunCurrencyStore.LoadCurrency`); provide "start another run / return to camp" buttons → `RunManager.StartRun()` / reload. Make failure reasons readable (frustration control).

### 5. Editor one-click setup tool (new)
- `Assets/C#/Editor/RogueSetup.cs` (new)
  - **What / why**: idempotently assembles items 1-4 into a scene via menu, avoiding hand-written Scene YAML; aligns with `CompositionSetup` / `UiShowcaseSetup`.
  - **How**: `[MenuItem("Tools/局会话/Setup Rogue Demo")]`: find/create `RunManager` on the scene root, wire the player / enemies / UI references, generate the fragment prefab and altar / settlement panels (via `PrefabUtility` / runtime creation), idempotent (re-running does not stack). Produces a Play Mode-ready RogueDemo scene (or reuses `SampleScene`).

### 6. RunManager minor adjustment (only if needed)
- `Assets/C#/RunManager.cs` (modify, only if a gap exists)
  - **How**: only if the room flow needs to expose current room type / alive count or a unified enemy death hook, add the minimal public methods; **do not** change the existing `ApplyModifier` / `EndRun` / persistence logic. Skip if not needed.
