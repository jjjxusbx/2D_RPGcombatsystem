> **版本**: v0.2

> **负责人**: 战斗系统程序员
> **状态**: 规划阶段
> **前置版本**: v0.1 ✅ / v0.1.5 ✅（Rogue 跑局循环已验证）

## 一、目标与范围

### 1.1 核心目标

**统一输入入口**：将 Unity 新输入系统（Input System Package）接入战斗管线，并将跳跃/射箭从遗留脚本 `跳跃射箭` 迁移进 FSM，消除双写 `rb.linearVelocity` 的风险。

### 1.2 业务价值

| 问题 | 影响 | 本版本解决 |
|------|------|-----------|
| 旧 `Input` API + 新 Input System 双模式并存 | 重复触发风险、维护两套键位配置 | 统一为 Input System 单一入口 |
| `跳跃射箭` 与 `基础移动` 双写速度 | 移动/跳跃冲突、状态卡死 | FSM 单一接管，消除竞争 |
| `跳跃射箭` 被禁用 | 玩家无法跳跃/射箭 | v0.2 后可用 |
| 键位配置散落各脚本 | 难以支持玩家自定义键位 | Input Action Asset 集中管理 |

### 1.3 范围边界

**纳入范围**:
- Unity Input System 接入（`.inputactions` 资产配置 + `PlayerInput` 组件）
- `跳跃射箭` 逻辑迁移：
  - 跳跃 → FSM 新增 `JumpState`
  - 射箭 → FSM 武器切换体系（剑/弓）
- 旧 `Input` API 调用清零（除编辑器工具）
- `跳跃射箭` 删除/禁用（迁移完成后）

**不纳入范围**:
- `基础移动` 架构变更（v0.1 仲裁已解决双写问题，v0.2 不触碰）
- BuffController/InventoryManager 扩展
- 新的游戏玩法机制
- 存档系统升级
- 性能优化（对象池等）

## 二、技术架构

### 2.1 输入系统迁移方案

#### 现状分析

**当前状态**:
- Unity Input System 包已安装（`com.unity.inputsystem: 1.14.0`）
- 存在两份未接入的 `.inputactions` 资产：
  - `Assets/InputSystem_Actions.inputactions`
  - `Assets/Hero.inputactions`
- `PlayerInputReader` 使用旧 `Input` API（`GetAxis`/`GetKey`/`GetMouseButton`）
- `跳跃射箭` 直接在 `Update` 内读 `Input.GetKeyDown(KeyCode.Space)` 和 `Input.GetMouseButtonDown(0)`

**风险**:
- `activeInputHandler` 双模式下旧 `Input` 与新 Input System 同时触发
- 键位配置散落在 `PlayerInputReader` 的 `SerializeField` 和 `跳跃射箭` 硬编码

#### 目标架构

**单一输入入口**（Input System → `PlayerInputReader` → FSM）:

```
InputActionAsset (Hero.inputactions)
  ↓ PlayerInput 组件（事件模式 Event Mode）
  ↓ PlayerInputReader 实现 IPlayerIntentProvider
  ↓ CombatStateMachine.Update() 单帧单次 GetIntent()
  ↓ currentState.Execute(ctx)
```

**输入映射表**（Input Action Map）:

| Action | 绑定 | 类型 | 说明 |
|--------|------|------|------|
| Move | WASD / 左摇杆 | Value<Vector2> | 移动方向 |
| Look | 鼠标 / 右摇杆 | Value<Vector2> | 瞄准方向（射箭用） |
| Sprint | Left Shift / 手柄按钮 | Button | 奔跑 |
| Attack | 鼠标左键 / 手柄按钮 | Button | 近战攻击 |
| Dodge | 空格 / 鼠标右键 / 手柄按钮 | Button | 闪避 |
| Jump | 空格（与闪避互斥） | Button | 跳跃 |
| Shoot | 鼠标左键（长按）/ 手柄扳机 | Button | 射箭（武器切换为弓时） |
| Skill | Q / 手柄肩键 | Button | 施放技能 |

**互斥逻辑**:
- 跳跃与闪避共享 `Space` 键，通过 FSM 当前状态决定行为：
  - `IdleState`/`MoveState` → `Space` = 跳跃
  - 任意状态 → `DodgePressed` = 闪避（优先级高于跳跃）
- 攻击与射箭共享鼠标左键：
  - 武器状态为"剑" → `AttackPressed` = 近战攻击
  - 武器状态为"弓" → `AttackPressed` = 射箭

**Step 1: 配置 Input Action Asset**

```csharp

// 2. 创建 Action Map "Player"
// 3. 按上表配置 Actions + Bindings
// 4. 生成 C# 类（Generate C# Class 勾选）

```

**Step 2: 重写 PlayerInputReader**

```csharp
// 新增：支持 Input System 事件回调 + 旧 Input 双模式开关（过渡期用）
public class PlayerInputReader : MonoBehaviour, IPlayerIntentProvider
{
    [Header("输入模式")]
    [SerializeField] private bool useNewInputSystem = true; // v0.2 默认 true

    private HeroInputActions _inputActions;
    private PlayerIntent _cachedIntent;

    private void Awake()
    {
        if (useNewInputSystem)
        {
            _inputActions = new HeroInputActions();
            _inputActions.Player.Move.performed += OnMove;
            _inputActions.Player.Look.performed += OnLook;
            _inputActions.Player.Attack.performed += OnAttack;
            // ... 绑定其他 actions
        }
    }

    private void OnMove(InputAction.CallbackContext ctx)
    {
        _cachedIntent.MoveDirection = ctx.ReadValue<Vector2>();
    }

    // ... 其他回调

    public PlayerIntent GetIntent()
    {
        if (useNewInputSystem)
        {
            return _cachedIntent; // 从事件回调缓存读取
        }
        else
        {
            // 旧 Input API 路径（过渡期保留，v0.3 删除）
            return BuildIntentFromOldInput();
        }
    }
}
```

### 2.2 FSM 扩展：JumpState + 武器切换

#### 2.2.1 JumpState

**职责**:
- 执行跳跃物理（`rb.linearVelocity = new Vector2(rb.linearVelocity.x, jumpForce)`）
- 触发跳跃动画（`SetTriggerIfExists(anim, "Jump")`）
- 监听 `OnCollisionEnter2D` 检测地面（或使用 `Physics2D.OverlapCircle` 地面检测）
- 跳跃结束后自动切换到 `FallState` → `IdleState`（落地检测）

**状态转换**:

```
IdleState / MoveState
  ↓ JumpPressed (Space)
JumpState (起跳)
  ↓ 空中（无输入检测）
FallState (下落)
  ↓ IsGrounded() == true
IdleState / MoveState (落地)
```

**参数配置**（`PlayerConfig` 或直接 `SerializeField`）:
```csharp
[Header("跳跃")]
[SerializeField] private float jumpForce = 12f;
[SerializeField] private float gravityScale = 1f;
[SerializeField] private Transform groundCheck;
[SerializeField] private float groundCheckRadius = 0.2f;
[SerializeField] private LayerMask groundLayers = ~0;
```

#### 2.2.2 武器切换体系

**设计决策**：武器状态由 `CombatContext` 持有，FSM 根据当前武器决定行为。

**武器枚举**:
```csharp
public enum WeaponType
{
    Sword,  // 近战（默认）
    Bow     // 远程（射箭）
}
```

**FSM 武器切换逻辑**:
- `IdleState` / `MoveState`：监听 `WeaponSwitchPressed`（数字键 1/2 或滚轮）
- 切换时更新 `CombatContext.CurrentWeapon`
- `AttackState` 根据 `CurrentWeapon` 执行不同行为：
  - `Sword` → 近战攻击（`HitBoxController` 触发）
  - `Bow` → 射箭（`SkillExecutor` 投射物逻辑）

**射箭迁移**（从 `跳跃射箭.FireArrow()` 迁移）:
```csharp
// SkillData 配置（ScriptableObject）
[CreateAssetMenu(menuName = "战斗/技能/弓箭射击")]
public class BowShootSkillData : SkillData
{
    public GameObject arrowPrefab;
    public float arrowSpeed = 14f;
    public float arrowDamage = 10f; // 或从 Atk × 倍率计算
    public int maxAmmo = 5;
    public float ammoRefillDelay = 1.2f;
}

// SkillExecutor 新增分支
public void Execute(SkillData skill, CombatContext ctx)
{
    if (skill is BowShootSkillData bowSkill)
    {
        FireArrow(bowSkill, ctx);
    }
    else
    {
        // 现有技能执行逻辑
    }
}
```

**箭矢数量 UI**: 迁移 `跳跃射箭.ammoText` 逻辑到 `SkillExecutor` 或新 `AmmoUI` 组件。

### 4.2 FSM 状态扩展

#### JumpState.cs（新增）

```csharp
namespace CombatSystem.State
{
    public class JumpState : ICombatState
    {
        private float _jumpForce;
        private float _gravityScale;
        private Transform _groundCheck;
        private float _groundCheckRadius;
        private LayerMask _groundLayers;
        private Rigidbody2D _rb;
        private Animator _anim;

        public void Enter(CombatContext ctx)
        {
            _rb = ctx.Rigidbody2D;
            _anim = ctx.Animator;
            _jumpForce = ctx.Config.jumpForce;
            _groundCheck = ctx.GroundCheck;
            _groundCheckRadius = ctx.Config.groundCheckRadius;
            _groundLayers = ctx.Config.groundLayers;

            // 起跳
            _rb.linearVelocity = new Vector2(_rb.linearVelocity.x, _jumpForce);
            PlayerAnimationPresenter.SetTriggerIfExists(_anim, "Jump");
            RogueDiag.Log("[Diagnostics] JumpState: 起跳");
        }

        public void Execute(CombatContext ctx)
        {
            // 空中检测
            if (IsGrounded())
            {
                ctx.StateMachine.ChangeState<IdleState>();
            }
        }

        public void Exit(CombatContext ctx)
        {
            RogueDiag.Log("[Diagnostics] JumpState: 落地");
        }

        private bool IsGrounded()
        {
            if (_groundCheck == null) return false;
            return Physics2D.OverlapCircle(_groundCheck.position, _groundCheckRadius, _groundLayers);
        }
    }
}
```

## 六、迁移策略与风险

### 6.1 迁移顺序

```
Week 1:
  1. 配置 InputActionAsset（Hero.inputactions）
  2. 生成 C# 类 + PlayerInputReader 重写
  3. 集成测试（输入 → FSM → 移动/攻击/闪避）

Week 2:
  4. 新增 JumpState
  5. 武器切换体系 + BowShootSkillData
  6. 删除 跳跃射箭.cs
  7. 完整回归测试
```

### 6.2 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| Input System 事件丢失 | 中 | 高 | 过渡期保留双模式开关 `useNewInputSystem`，失败可快速切回 |
| JumpState 地面检测误判 | 低 | 中 | 增加 `groundCheckRadius` 可配置项，Play Mode 实测不同地形 |
| 手柄映射冲突 | 中 | 低 | 提供"重置为默认键位"编辑器菜单 |
| 旧 Input 残留调用 | 低 | 低 | `git grep "Input.Get"` 提交前检查 |

### 6.3 回滚方案

若 Input System 集成失败，保留 `PlayerInputReader.useNewInputSystem = false` 可切回旧 `Input` API，不影响 v0.1.5 的 FSM 战斗逻辑。
