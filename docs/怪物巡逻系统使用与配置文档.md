# 怪物巡逻系统使用与配置文档

> 适用项目：Unity 6 2D 俯视角模拟经营 Demo
> 依赖：`com.unity.ai.navigation`（已安装，`NavMeshSurface` / `NavMeshAgent`）

---

## 一、模块组成

| 文件 | 职责 |
|------|------|
| `Assets/C#/Execution/AI/MonsterPatrolController.cs` | 怪物 AI 状态机（Idle / Patrol / Chase）+ NavMeshAgent 驱动 |
| `Assets/C#/Execution/AI/MonsterPatrolPath.cs` | 巡逻路径点容器（Scene 视图可视化连线） |
| `Assets/C#/Editor/MonsterPatrolSetup.cs` | 一键搭建演示环境（菜单工具） |
| `Assets/C#/EnemyBase.cs` | 已改造：移动控制移交巡逻控制器，保留攻击/受击/击退 |

---

## 二、快速开始（一键搭建）

1. 在 Hierarchy 中**选中要配置的怪物**（如 `Slime_sheet`）。
2. 打开菜单 `Tools → 怪物巡逻 → Create Patrol Demo Setup`。
3. 工具会自动：
   - 创建导航地面 `MonsterNav_Ground`（XZ 平面薄板 + `NavMeshSurface`）并烘焙
   - 创建巡逻路径 `MonsterPatrol_Path`（3 个路径点）
   - 为选中怪物挂载 `NavMeshAgent` + `MonsterPatrolController`，关联路径与玩家
4. 点击 Play 验证。

> 如果只改了地面/障碍，需要重新烘焙：`Tools → 怪物巡逻 → Bake NavMesh Only`。

## 三、Inspector 参数说明（MonsterPatrolController）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `enemy` | 自动获取 | EnemyBase 引用 |
| `patrolPath` | 无 | 巡逻路径组件引用 |
| `target` | 自动获取 | 玩家 Transform |
| `patrolSpeed` | 1.8 | 巡逻速度 |
| `chaseSpeed` | 3.2 | 追击速度 |
| `detectionRadius` | 5 | 进入追击的检测半径 |
| `attackRange` | 1.2 | 进入后停止移动并攻击 |
| `loseTargetDistance` | 7 | 超过后放弃追击，返回巡逻 |
| `arrivalDistance` | 0.25 | 判定到达路径点的距离 |
| `idleTime` | 1 | 到达路径点后停留时间 |
| `repathInterval` | 0.2 | 重新寻路间隔（防抖） |
| `playerMask` | 无 | 玩家所在 LayerMask（检测用） |

### 路径点配置（MonsterPatrolPath）

- 在 `MonsterPatrol_Path` 下创建空子物体作为路径点，拖入 `points` 列表。
- 勾选 `loop`：走完最后一个点后回到第 0 个点（循环）。
- 不勾选 `loop`：到达端点后**反向折返**（往返巡逻）。
- Scene 视图中黄色小球 + 连线即为路径。

## 四、2D 项目 NavMesh 适配说明（关键）

本项目为俯视 2D（Rigidbody2D，XY 平面），而 `NavMeshAgent` 是 3D 组件，在 **XZ 平面**寻路。`MonsterPatrolController` 内部完成坐标映射：

- 世界坐标 `(x, y)` → NavMesh 坐标 `(x, 0, y)`（`ToNavPosition`）
- NavMesh 坐标 `(x, 0, z)` → 世界坐标 `(x, z)`

因此：
- **地面必须烘焙在 XZ 平面**（工具创建的薄板位于 Y=-0.25，顶面约 Y=0）。
- 怪物、路径点、玩家仍正常摆放在 2D XY 平面。
- `NavMeshAgent` 的 `updatePosition/updateRotation` 已设为 `false`，由控制器手动同步。

### NavMesh 烘焙注意事项

- 地面使用 **3D Collider**（工具自动创建 Cube），2D Collider（Tilemap 等）不会被 `NavMeshSurface` 采集。
- 若场景已有 2D Tilemap 地形，需要额外在对应位置摆放 3D 碰撞体（或把地形物体加 `MeshCollider`）才能纳入烘焙。
- 障碍物同样需要 3D Collider。

## 五、状态机说明

```
          DetectPlayer(进入 detectionRadius)
   Idle ────────────────────────────────┐
    │                                    │
    │ 无路径点                           ▼
    │                                Chase
    │                                    │
    │ 到达点后等待 idleTime              │ 玩家超出 loseTargetDistance
    ▼                                    │
  Patrol ◄───────────────────────────────┘
```

| 事件 | 行为 |
|------|------|
| 启动且有路径点 | 从最近路径点开始 Patrol |
| 玩家进入 `detectionRadius` | 切 Chase，以 `chaseSpeed` 追击 |
| 玩家进入 `attackRange` | 停止移动，调用 `EnemyBase.CreatATKTrigger1()` 攻击 |
| 玩家超出 `loseTargetDistance` | 回到最近路径点继续 Patrol |
| 受击（`EnemyBase.IsGetHit`） | 暂停导航（isStopped + ResetPath），保留击退；受击结束 Warp 对齐后恢复 |
| 无路径点 | Idle，检测到玩家仍可追击 |

## 六、测试验证清单（Play Mode 手测）

1. **巡逻**：怪物在路径点间往返移动，到达后停留 `idleTime` 秒，路径平滑无抖动。
2. **追击**：玩家进入 `detectionRadius`，怪物立即切换追击并以 `chaseSpeed` 移动。
3. **攻击**：玩家进入 `attackRange`，怪物停住并触发攻击动画/伤害。
4. **回归**：玩家离开 `loseTargetDistance`，怪物回到最近路径点继续巡逻。
5. **受击**：玩家攻击怪物，怪物播放受击动画 + 击退，导航暂停；受击结束恢复巡逻/追击。
6. **边界**：
   - `MonsterPatrol_Path` 无路径点 → 怪物 Idle 不报错。
   - 目标在 NavMesh 外不可达 → 不卡死（走直线移动回退或等待）。
   - 未烘焙 NavMesh → 控制台应能通过 `MoveDirect` 直线移动，建议按第三节重新烘焙。

## 七、维护与优化建议

1. **坐标系约定固定**：所有使用 NavMesh 的 2D 单位都应遵循 `(x, y) ↔ (x, 0, y)` 映射，不要在其他脚本里再写一遍转换。
2. **性能**：`DetectionRadius` 使用 `Physics2D.OverlapCircle`，建议把玩家放到独立 Layer 并只匹配 `playerMask`，避免全场景物理查询。
3. **动画**：`SetRun` 已做 `IsRun` 参数防御；Slime 控制器无移动参数，如需移动动画可在 Animator 中新增 `IsRun` bool 并配置 Idle/Move 过渡。
4. **受击恢复**：`Warp` 到击退后位置后恢复寻路，避免击退期间 agent 路径残留导致抖动。
5. **对象池**：若大量怪物使用同一路径，可考虑将 `PatrolPath` 复用并共享，减少场景重复配置。
6. **状态扩展**：新增状态（如逃跑、回血）时在 `MonsterState` 枚举与 `Update` switch 中扩展，保持状态机单一职责。
