# UI 作品集设计说明：《地牢远征》界面设计与交互

> 定位：本作品集项目的"设计策略"章节。说明 6 个界面（Loading / 主界面 / 信息页 / 关卡选择 / 活动弹窗）的设计意图、视觉与交互取舍，以及为什么**不做战斗 UI**。

---

## 0. 插曲：为什么不做战斗 UI，重心放在界面设计与交互

这是一个常见且值得写进作品集的"设计取舍"：

- **作品集展示的是"界面设计师"的能力，而不是"游戏系统工程师"的能力。** 战斗 UI（技能冷却、血条浮动、伤害数字）的展示价值高，但它的成败主要由玩法数值与战斗节奏决定，界面本身能发挥的设计空间相对小、可读性门槛高。
- **6 个界面共同组成一条完整的"用户旅程"。** Loading → 主界面 → 关卡选择 → 活动弹窗，覆盖了游戏 UI 设计的核心命题：信息架构、层级导航、状态反馈、引导性设计、组件通用性。把它们做透，比在战斗 UI 上堆砌特效更能体现"界面与交互"的专业度。
- **战斗 UI 与这套演示正交。** 本项目的战斗逻辑（CombatSystem / TurnBased）是另一条技术线，且尚未稳定到适合承载作品集级的界面设计；把战斗 UI 单独抽走，反而能保证这条作品集线始终干净、可控、可运行。

一句话：**"做用户会反复看到、且决定留存感受的界面"**——这正是 Loading / 主界面 / 关卡选择 / 活动弹窗所在的位置。

---

## 1. 设计总纲：暗金地牢 × 像素风

- **风格**：暗色地牢 + 金色高光。统一色板（`UiTheme`）：夜黑、石色、金、焰橙、冰蓝，全界面共用，保证系列感。
- **字体**：正文用「字魂布丁体.ttf」（Assets 内中文 TTF，已在场景中配置），英文副标题用 Gixel（像素字体），保留作品集展示的"中西混排"细节。
- **素材**：全部复用 Assets/Arts 下现有资源——地牢背景、石砖、吊灯（可交互吊灯资源包）、角色立绘（Hero_Idle 切片）、UI 边框、背包图标、建筑与自然剪影。**零新素材**，突出"用有限素材做完整系统"的整合能力。
- **画布**：1920×1080 参考分辨率，Scale With Screen Size。

## 2. Loading 界面

**设计意图**：把"等待"变成"世界观前菜"。

- 深色地牢背景压暗 78%，顶部吊灯透出暖光 → 第一眼交代场景气质。
- 标题 LOGO（金色大标题 + 英文副标题）+ 版本号 + 底部轮播提示文案（3 条地牢玩法提示）。
- 进度条：easeOutQuad 缓动 0→100%，文案随进度变化（读取地图 / 召唤小队 / 淬炼武器 / 点燃火炬），进度满后自动跳转主界面。
- **交互要点**：零操作自动流转；进度感 + 文案同步，让等待有"被讲述"的感觉。

## 3. 主界面

**设计意图**：视觉冲击力 + 信息分层（Banner > 玩家信息 > 导航入口）。

- **分层背景**：地牢场景 → 暗角 → 底部建筑剪影（左塔 + 右塔），制造纵深与"城堡前广场"的舞台感。
- **Banner**：金色描边横幅，右侧英雄立绘，左侧标题 + 副标题 + "立即出发 →"CTA（与底部"关卡"入口行为一致，验证多入口收敛到同一流程）。
- **玩家信息栏**：头像（英雄立绘）、名称、等级/战力、金币 / 体力 / 生命三个资源图标行。
- **导航按钮组**（底部横排 5 枚）：关卡（金）、公告、活动（焰橙高亮）、背包、设置。图标 + 标题 + 副标题三段式。
- **交互要点**：视觉层级自上而下递减；CTA 与导航的"双入口一致"，是主界面信息架构设计的核心考点。

## 4. 信息页（通知页）

**设计意图**：考信息架构与排版——TabBar 分类 + 信息列表 + 详情弹窗三层结构。

- 顶部 TabBar（公告 / 版本更新 / 邮件）：选中项金色高亮、未选中石板色，切换即换列表。
- 列表行：标题（加粗）+ 时间（右上）+ 摘要 + 箭头，整行可点。
- 点击行 → 打开详情弹窗（标题 + 时间 + 正文），验证"列表 → 详情"的通用层级。
- **交互要点**：三组数据并行展示"同一组件不同内容"；Tab 高亮态与选中态反馈清晰。

## 5. 关卡选择界面

**设计意图**：核心交互——用楼层/房间模型表达地牢肉鸽的进度与引导。

- 三层楼（幽暗走廊 / 腐化墓室 / 深渊核心），每层 3 个房间卡片，自上而下难度递增。
- 房间三态：**已完成**（绿底 + ✓ + 星数）、**已解锁**（亮石色 + 星级）、**未解锁**（灰底 + 🔒）。
- 引导性：顶部一行指引文案"通关当前层全部房间可解锁下一层"；未解锁房间点击 → 提示"通关 xxx 后解锁"，明确下一步。
- 已解锁未通关房间 → 关卡详情弹窗（类型 / 难度星级 / 描述 / 奖励图标行 / 敌人信息 / 确认进入 / 再想想）。
- **交互要点**：状态可视化（三态）+ 失败反馈（锁定提示）+ 确认前置（详情弹窗），是"关卡选择的引导性"的完整闭环。

## 6. 活动弹窗

**设计意图**：弹窗组件通用性 + 吸引力。

- 从主界面"活动"入口打开（弹窗独立于页面栈）。
- 结构：标题 + 活动时间副标题 + **可滚动奖励列表**（6 行奖励，图标 + 名称 + 数量，超过视口可滚动，验证 ScrollRect 通用性）+ 底部操作区。
- 操作反馈：**领取** → 按钮置灰 + 状态文案变绿"奖励已发放"；**去参与** → 状态文案切换"已前往关卡选择"。关闭按钮 ✕ + 遮罩点击关闭，双关闭路径。
- **交互要点**：点击有即时反馈（非静默）；遮罩点击 = 二级确认，是移动端弹窗的行业惯例。

## 7. 页面流转图

```
[打开 UiShowcase 场景 → Play Mode]
        │
        ▼
  Loading（自动 0→100%，easeOut）
        │ 完成
        ▼
  主界面 ──┬── 点击「关卡 / Banner CTA」──► 关卡选择（页面栈 Push，返回 Pop）
        │      │
        │      └── 点房间 ──► 关卡详情弹窗（弹窗栈，遮罩/✕ 关闭）
        │                 └─ 确认进入 ─► Toast 提示
        │      └── 点未解锁房间 ──► Toast 锁定提示
        │
        ├── 点击「公告」────────────► 信息页（TabBar 公告/版本/邮件 → 详情弹窗）
        │
        ├── 点击「活动」────────────► 活动弹窗（弹窗栈，领取/去参与反馈）
        │
        ├── 点击「背包 / 设置」────► Toast 占位提示
        │
        └── 各页「← 返回」─────────► 页面栈 Pop 回主界面
  全局：Esc = 优先关弹窗，其次返回上一页
```

规则：
- **页面栈**：一次只显示一个页面，Push 隐藏当前页，Pop 恢复上一页；Loading 为根页，不可被弹出。
- **弹窗栈**：独立于页面栈，挂载在更上层；关闭按钮 / 遮罩点击 / Esc 三种方式关闭。

---

## 8. 框架一句话

**UiShowcase 命名空间**：`UiPageStack`（页面栈：Push/Pop/Replace）+ `UiDialogStack`（弹窗栈：Open/CloseTop/ClearAll）+ 通用组件（`ProgressBar`、`TabBar`、`ModalDialog`、`ListRow`、`UiFactory`），全部由组合根 `UiShowcaseBootstrap` 在 Awake 显式装配并注入资源表，**无全局单例、不依赖 AssetDatabase**（运行时通过序列化字段引用素材）。

## 9. 验证方式

- 打开 `Assets/Scenes/UiShowcase.unity` 直接进 Play Mode：Loading → 主界面全流程可见。
- 编辑器菜单 `Tools/UI作品集/装配并验证`：重建场景或回填素材引用；`仅验证素材引用`：输出缺失清单。
- 控制台日志前缀 `[UiShowcase]`：资源缺失输出 LogWarning 不静默。
