# 策划流程与双档方案（v0.1）

> 定位：以游戏架构师视角整理的策划方法论 + 《灰烬矿脉》落地双档方案。
> 参考：《2D Game Art, Animation, and Lighting for Artists》（Unity 官方，John E. Wharff，作者即 Unity 2D 演示《Dragon Crashers》艺术总监）、Unity 官方 2D 光照文档、现有战斗代码。
> 状态：调研结论，未涉及代码改动。

---

## 一、电子书要点（2D 美术/动画/光照）

### 章节结构与核心结论

| 章节 | 关键结论 | 对本项目意义 |
|---|---|---|
| 2D 项目设置 | URP + 2D Renderer，正交相机，2D 模板（含 2D Animation、Pixel Perfect、Sprite Shape 等包） | 光照体系必须走 Light 2D |
| 美术决策先行 | mockup 先验证风格；**排序分层（Sorting Layer）必须在资源制作期定好** | 现场景排序层隐式，需尽早显式化 |
| 精灵编辑器 | PPU/轴心/九宫格/图集统一规范 | 导入即设置，避免返工 |
| Tilemap | 环境与关卡设计 | 现场景已是 Tilemap，符合 |
| 2D 骨骼动画 | 逐帧/骨骼/shader 三类按元素选 | 小怪逐帧、BOSS 可上骨骼 |
| 2D 光与影 | Light 2D 四模式：自由形式/精灵/聚光/全局；法线贴图+阴影 | 吊灯资源包即此体系案例 |
| 2D 优化 | 2D 光源批处理、Sprite Atlas、Pixel Perfect | 上线前做 |

### 官方文档核实（Unity Manual, URP 2D lighting）

- 2D 光照系统对 Sprite Renderer / Tilemap Renderer / Sprite Shape Renderer 无缝集成，针对移动端与跨平台优化。
- 精灵受光需 `Sprite-Lit-Default` 材质（场景默认）；自定义受光效果用 Shader Graph。
- Light 2D 组件负责打光，Shadow Caster 2D 负责定义阴影。

### 直接可借鉴

本书配套示例《Dragon Crashers》是**横版滚动 idle RPG 垂直切片**，与本项目（横版动作刷宝）同类，其光照/排序/动画流程可作模板。

## 二、游戏策划流程（架构师视角）

### 完整流程阶段

| 阶段 | 关键产出物 | 验收标准 |
|---|---|---|
| 概念 | 一页纸 pitch、核心循环图、情绪板 | 一句话讲清"谁玩、做什么、爽点在哪" |
| 立项/垂直切片 | 垂直切片（1 关卡+核心战斗+3~5 数值）、GDD 骨架、里程碑拆解 | 可演示核心乐趣；风险已暴露；可估算工期 |
| 正式制作 | 完整 GDD、数值表、关卡文档、系统规格、Art bible | 各模块有负责人与依赖图；每日可编译可玩 |
| Alpha | 全功能未打磨、可全程通关 | 核心循环闭环、无阻断性 Bug、数值可玩 |
| Beta | 内容冻结，只做平衡与修 Bug | 平衡数据定稿、崩溃率达标、新手引导通过 |
| 上线/复盘 | 上线清单、运营埋点、复盘报告 | 留存/时长数据回填下一迭代 |

### 策划文档体系

| 文档 | 解决什么问题 | 写给谁 | 详细程度 |
|---|---|---|---|
| GDD | 游戏是什么 | 全组+投资人 | 模块级，不写实现 |
| 关卡设计文档 | 这段怎么玩 | 关卡美术+程序 | 敌人布点、节奏表、演出时间轴 |
| 数值表 | 数值从哪来 | 策划自己+程序 | 白盒数值+公式+来源注释 |
| 系统设计文档 | 系统间怎么交互 | 程序 | 状态流、边界条件、错误处理 |
| 竞品拆解 | 借鉴什么 | 决策者 | 循环拆解+数值反推+证据 |

### 数值策划基础

- 数值表结构：基础值 + 成长曲线表 + 公式列 + 来源列。
- 伤害公式三型：攻击-防御 / 攻×(1-减伤) / 攻×倍率×暴击。
- 经济：产出 - 消耗 - 通胀控制。
- 平衡迭代：白盒（设定预期 DPS/击杀时间）→ 跑测采集 → 调参 → 回归。单点数值改动用参数化配置，不硬编码。

### 关卡策划基础

- 节奏 = 战斗(紧张)-探索(喘息)-奖励(正反馈) 三段循环，每 3~5 分钟一个波峰。
- 敌人组合 = 基础兵 + 远程 + 精英的"压力三角"。
- BOSS = 阶段(2~3 段血量) + 招式模板(快慢/范围/突进三型) + 弹幕随阶段提升 + 处决/战利品高光。

### 玩法策划基础

- 核心循环分局内（进房→战斗→掉落→变强→进房）与局外（跑局→攒货币→永久解锁→再跑局）。
- 情绪曲线：压力蓄积→爆发释放。
- 奖励：即时（掉落/特效）与延迟（局外解锁）双通道。
- 挫败感控制：死亡惩罚可承受（保留局外货币而非全清零）+ 失败原因可读。

## 三、《灰烬矿脉》双档方案

项目定位回顾：Unity 6 / 2D 横版侧视 / 剑近战+弓瞄准 / FSM 战斗（Idle/Move/Attack/Dodge/CastBuff）/ ChaState 统一属性（Attribute 五段式 + ModifierType）/ SkillData+MagicEffect+BuffData 配置驱动 / PlayerCombatBootstrap 装配根 + RuntimeDiagnostics 自检 / 输入已配置化键位（仍旧 Input）。

### A. 极简版 Rogue（2 周验证）

- **核心循环**：进房间 → 清怪 → 掉"灰烬碎片" → 房内三选一强化 → 下一房 → BOSS 房 → 死亡/通关结算。
- **局内成长最小闭环**：杀怪掉碎片 → 祭坛房用碎片兑换强化（AttributeModifier 三选一：+Atk / +MaxHealth / +AttackRate）→ `ChaState.ApplyModifier(source=局会话)` 即时生效，跑局结束统一 `RemoveModifiersFromSource` 清空。**全部用现成 API，不动 BuffController。**
- **死亡惩罚**：本局碎片全部丢失，仅按击杀数给少量局外货币（积累用于后续解锁）。
- **必做 5 个数值**（全部已存在于 ChaState，零新增属性）：Atk / MaxHealth / AttackRate / MoveSpeed / Growth。
- **验收**：一局可循环 3+ 房间；强化即时生效（面板可见）；死亡结算回营地；重启后属性还原。

### B. 标准版 Rogue（4-6 周）

- **局内构筑**：武器（剑/弓两系，SkillData 数据行）、技能（MagicEffect 配置）、词条（AttributeModifier 组合，如"普攻附带灼烧=命中施放 Buff"）、Buff 联动（BuffData 互斥组：火焰系 vs 冰霜系）。构筑深度靠**数据行+修饰器组合**实现，不改核心流程。
- **局外解锁**：局内货币解锁新武器/技能槽/起始属性；存储走 SaveManager（需扩展：无原子写入、需版本号）。
- **房间类型**：战斗房 / 事件房(选择支) / 商店房(碎片消费) / 精英房(高词条掉落)。房间序列 = 种子化随机 + 保底规则（前 3 房必战斗，BOSS 房前置商店）。
- **BOSS 设计**：两型 BOSS，2 段血，招式=冲刺+扇形喷吐+召唤小怪，阶段切换触发演出（Cinemachine Impulse）。
- **数值体系**：双币经济（碎片=局内 / 晶核=局外）；难度曲线=房序×敌人强度表（白盒）；掉落表结构=`LootTable(权重列表{itemId,weight,minQty,maxQty}) + 词条池(稀有度权重)`，掉落概率随局深度提升。

### C. 代码映射（复用/新增/重写）

| 模块 | 极简版 | 标准版 |
|---|---|---|
| ChaState 属性表 | **直接复用**，8 属性齐全 | 复用；新增词条=新 AttributeModifier 行；如需暴击率/暴伤走新增 statId 注册 |
| Attribute / ModifierType | **复用**；三段式足够 | 复用；词条=Modifier 组合 |
| SkillData / MagicEffect / BuffData | 复用；新技能=新数据资产 | 复用；事件房/陷阱也走 MagicEffect 数据 |
| FSM 状态 | **复用现有状态**，本档不新增 | 复用；BOSS 阶段用参数化（换招式表）而非新状态机 |
| CombatStateMachine | 暂不可复用→**本档不依赖其扩展** | 三连击/取消链需**重写约束**（Attack 退出约束曾拒绝 Idle，已修复） |
| BuffController | 暂不可复用→**本档不用**，Modifier 直连 | 需补事件/回滚后才可依赖 |
| InventoryManager | 暂不可复用→**本档无背包**，掉落即结算 | 局内背包**新写轻量实现**（局内临时，不接全局存档） |
| PlayerCombatBootstrap + RuntimeDiagnostics | **复用**；新增 RunManager 作局内装配根 | 复用；RunManager 扩展局外货币与解锁数据流 |

### D. 表现层清单（组件级，按难度）

| 难度 | 内容 | Unity 组件级落地 |
|---|---|---|
| 简单 | 吊灯交互 | Rigidbody2D + BoxCollider2D + Hinge Joint2D（勾 Use Limits，Angle Limits ±46°，Connected Anchor=悬挂点）+ 鼠标点击反向 AddForce(Impulse) + Light2D Intensity 曲线闪烁。**资源包已就绪** |
| 简单 | 氛围光照 | Light 2D 全局光（暗）+ 精灵光叠加，URP 2D 体系 |
| 简单~中 | 掉落物表现 | 精灵 + Light 2D 光环；拾取半径走 ChaState.PickupRange |
| 中 | 打击反馈 | ChaState.onDamaged 订阅 → 闪白(SpriteRenderer) + 击退(Rigidbody2D) + 顿帧(Time.timeScale 0.05s) + 粒子火花 |
| 中 | 角色动画 | 逐帧 spritesheet（Animator 参数 IsRun/ATK_1，现有）为主；BOSS 可上 2D Animation 骨骼 |
| 中~难 | BOSS 演出 | Cinemachine Impulse 震屏 + 阶段切换灯光变化 |

## 四、信息缺口与风险

- 电子书 PDF 未逐页读取（Shell 断流），要点来自官方章节清单 + 社区逐章翻译 + Unity 官方博客；如需逐页级细节（具体 shader 配置）需稳定终端后重试。
- 排序分层（Sorting Layer）目前隐式依赖 Sprite 默认层，应作为正式制作期的第一批规范制定。
- 掉落/装备/局外解锁依赖 SaveManager 扩展（版本号 + 原子写入），列入 v0.1.5 里程碑前置条件。
